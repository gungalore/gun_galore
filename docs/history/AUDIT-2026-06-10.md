### Biggest risk
**The platform is wired entirely on test/sandbox/dev credentials in production** — Clerk dev instance (~100-user cap), VerifyNow sandbox (fake KYC passes), Stitch test/mock (no money collected). Plus two code-level money CRITICALs: offer checkout lets a buyer pay a cheap price for an expensive listing (C1), and auction winners can never pay (C2).

### Verdict
🔴 **NOT READY TO LAUNCH.** The config CRITICALs (operator) + the two money-path code CRITICALs (Claude) must be fixed and tested first. The architecture is sound — failures are concentrated in launch config and two checkout code paths, not the core design.

## 2. CRITICAL

### C1 — Offer checkout never binds the offer to the listing being bought (price substitution) `[me]`
`backend/src/payments/transactions.service.ts:87-122` — offer loaded by `offerId` only; no `rawOffer.listingId === dto.listingId` check; price taken from offer; listing reserved/sold separately.
**Impact:** A buyer with any accepted offer on a cheap Take-a-Shot listing can check out pointing at a *different, expensive* listing — pays the cheap amount, the expensive listing is marked SOLD. Direct inventory theft.
**Fix:** reject if `rawOffer.listingId !== dto.listingId` (or derive the listing from the offer); add a regression test.

### C2 — Auction winners can never pay; checkout 404s on a won auction `[me]`
`frontend/app/checkout/[listingId]/page.tsx:33-34` (requires ACTIVE + BUY_NOW); win-token redirect `backend/src/actions/action-tokens.controller.ts:584`.
**Impact:** A finalised auction becomes PAYMENT_PENDING + AUCTION, but the "you won — pay now" link lands on a page that rejects both conditions and 404s. No winner-pay path exists anywhere. Every won auction is dead money.
**Fix:** add a winner-pay path that accepts a PAYMENT_PENDING AUCTION listing for the authorised winner and charges the winning bid.

### C3 — Clerk on TEST keys / development instance in production `[operator]`
Live HTML serves `pk_test_…` → `super-stinkbug-64.clerk.accounts.dev`.
**Impact:** dev instances cap ~100 users and refuse sign-ups past it (registration silently breaks at launch), carry dev branding, weaker session posture.
**Fix:** create a Clerk production instance, configure domain + DNS, swap to `pk_live`/`sk_live` (frontend rebuild + backend secret + re-create user webhook).

### C4 — VerifyNow KYC in SANDBOX in production `[operator]`
`backend/src/main.ts:37-41` (WARN-only, doesn't block boot); `.env` = sandbox.
**Impact:** sandbox returns canned PASS — every seller "verifies" with fake details. KYC is the seller-trust anchor for a regulated firearms marketplace. Serious regulatory exposure.
**Fix:** `VERIFYNOW_MODE=production` (+ confirm credits), promote the WARN to a hard throw.

### C5 — Live checkout is Stitch on TEST creds; silent MOCK fallback (no money taken) `[operator]`
`backend/src/payments/stitch.service.ts:175-181` (mock checkout when unconfigured), `:329-333` (mock refund); `.env` has `STITCH_CLIENT_ID=test-…`.
**Impact:** real sales hit sandbox (no settlement) or mock (orders marked paid without taking money). The FNB pivot is plan-only — no FNB code exists — so Stitch is genuinely the live path.
**Fix:** provision live Stitch creds + one real end-to-end test sale; OR confirm FNB-first (that module must be built first). Don't flip payment env without operator sign-off.

## 3. HIGH

- **H1 — Featured-slot bids marked paid with a fake payment ID** `[me]` — `featured.service.ts:528-544,847-861`. Featuring is free, revenue dashboard reports phantom income, force-evict "refunds" a non-existent payment. **Fix:** block featured binding until a real Stitch charge is wired; exclude from revenue.
- **H2 — Abandoned/failed/expired checkouts strand the listing in PAYMENT_PENDING forever** `[me]` — `transactions.service.ts` reserve at `:187`, verify-result never reverts, webhook only on success, no reconcile cron (auctions too). **Fix:** ship the reconcile cron + Stitch expired/cancelled webhook.
- **H3 — Clerk `user.deleted` hard-deletes; POPIA erasure impossible for transacted users** `[me]` — `users.service.ts:147-149` `deleteMany`, FK RESTRICT. **Fix:** soft-delete + PII scrub, keep financial rows, wrap so webhook always 200s.
- **H4 — Raffle oversell + duplicate ticket numbers under concurrency** `[me]` — `raffles.service.ts:625,640-687`; no `@@unique([raffleId,ticketNumber])`. **Fix:** unique index + atomic conditional cap; re-check in confirm.
- **H5 — Backup raffle winners get a zero-length claim window** `[me]` — `raffles.service.ts:919-921,974-1013`. Promoted backup is already past deadline → force-forfeited next cron pass. **Fix:** reset claimDeadline on promotion before notifying.
- **H6 — Offer checkout understates total (button shows item-only; buyer charged item+shipping+fee)** `[me]` — `offer-checkout-form.tsx:285`. **Fix:** fetch quote, show full breakdown, gate the button on it.
- **H7 — `reloadOnOnline: true` hard-reloads on reconnect, wiping in-progress forms** `[me]` — `next.config.mjs:66`. KYC selfie/ID + checkout state lost when signal returns. **Fix:** `reloadOnOnline: false`.
- **H8 — No HSTS header on any route** `[operator]` — confirmed live (apex/API/static/ballistics). **Fix:** enable HSTS at Cloudflare (max-age ≥ 1yr, includeSubDomains).
- **H9 — No anti-clickjacking (no X-Frame-Options, no CSP frame-ancestors)** `[me]` — site embeddable in an attacker iframe. **Fix:** `headers()` block in next.config.mjs.
- **H10 — Prerendered HTML (incl. coming-soon + legal pages) sent with `s-maxage=31536000` (1 year)** `[me]` — confirmed live. Shared caches can pin "Coming Soon" after launch and stale legal copy for a year. **Fix:** short TTL + revalidation, not 1 year.
- **H11 — `STITCH_WEBHOOK_SECRET` unset → Stitch webhooks rejected (fail-closed)** `[operator]` — correct security, but no webhook ever processes (async EFT completions, reconciliation never fire). **Fix:** register webhook + set secret, or add a reconcile cron.

## 6. What Is Solid (don't spend launch effort here)

- **Admin authz model** — role re-loaded from DB on every superadmin mutation; signing secret fail-closed at boot. Forged/stale token can't escalate.
- **Payment anti-forgery** — `markPaid` re-verifies authoritative status + binds exact amount; attacker can't confirm an unpaid order (this is why several "unauth endpoint" findings are bounded, not catastrophic). Admin refund double-spend guarded atomically.
- **No SQLi / ReDoS / server SSRF** — all `$queryRawUnsafe` parameterized; bounded regexes; server fetches target env-configured hosts only.
- **Stitch webhook signature verification** — correct HMAC over `id.timestamp.rawBody`, 5-min window, fail-closed, raw body sourced correctly.
- **PWA design** — manifest, maskable icons, sw.js, /offline all correct + installable. (The "SW caches KYC PII" alarm was a false-positive — client-rendered, nothing reaches Cache Storage.)
- **CORS** is a strict allowlist, not a reflector; header-bearer auth (no cookies) means no CSRF-with-readback.
- **Firearm dealer-transfer routing** server-enforced both checkout paths; SAPS form is consistently 534 (271→534 done).
- **Compliance copy** — "escrow" only in one code comment, no user-facing string.
- **Infra** — Cloudflare fronting, origin Vultr IP not leaked, HTTP→HTTPS 301, no mixed content, static cached / HTML+API no-store, ballistics subdomain real + un-gated, auth-gated routes correctly 307 to sign-in.
